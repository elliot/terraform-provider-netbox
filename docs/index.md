# NetBox Provider

The NetBox provider manages objects in [NetBox](https://netboxlabs.com/oss/netbox/) 4.7 through its REST API.
Every CRUD collection of the NetBox 4.7 API is available as a resource (`netbox_<object>`), a single-object data source
(`data.netbox_<object>`) and a list data source (`data.netbox_<objects>`); see the resource index in the sidebar.

## Authentication

Only NetBox v2 API tokens (`nbt_<key>.<secret>`, NetBox 4.5+) are supported. Create one under
*Admin → API Tokens* or with `POST /api/users/tokens/provision/`. The token is sent as
`Authorization: Bearer nbt_<key>.<secret>`.

## Rate limiting, retries and delays

All requests of a provider instance share one client-side token bucket (`requests_per_second`, `request_burst`),
an optional fixed delay per request (`request_delay_ms`, plus `write_delay_ms` for writes), and an optional mutex that
serializes requests (`serialize_requests`) regardless of Terraform's `-parallelism`. HTTP 429 and 5xx responses are
retried with exponential backoff and jitter (`max_retries`, `retry_wait_min_ms`, `retry_wait_max_ms`), honouring the
`Retry-After` header. Every setting can also be provided through an environment variable (see below).

## Example Usage

```terraform
terraform {
  required_providers {
    netbox = {
      source  = "elliot/netbox"
      version = "~> 0.1"
    }
  }
}

# Credentials can also come from NETBOX_SERVER_URL and NETBOX_API_TOKEN.
provider "netbox" {
  server_url = "https://netbox.example.com"
  api_token  = var.netbox_token # a v2 token: nbt_<key>.<secret>

  # Client-side pacing shared by every resource (all optional).
  requests_per_second = 10    # token bucket, 0 disables
  request_burst       = 10
  request_delay_ms    = 0     # fixed artificial delay before every request
  write_delay_ms      = 0     # extra delay before POST/PUT/PATCH/DELETE
  serialize_requests  = false # force one request at a time
  max_retries         = 4     # 429/5xx are retried with exponential backoff
  retry_wait_min_ms   = 1000
  retry_wait_max_ms   = 30000
}

variable "netbox_token" {
  type      = string
  sensitive = true
}
```

## Conventions

* Foreign keys are numeric IDs named `<field>_id`; many-to-many relations are sets named `<field>_ids`.
* `tags` is a set of tag slugs. `custom_fields` is a native object (`{ cost_center = "CC-42", owner_site = 12 }`) whose
  names are validated against the NetBox definitions; only the keys present in the configuration are tracked. Other
  free-form JSON fields (`local_context_data`, `data`, ...) are JSON strings (`jsonencode({...})`).
* Choice fields accept the machine value (`active`, `1000base-t`, ...). Attributes with a server-side default are
  `Optional` + `Computed`.
* Every resource can be imported by its NetBox ID (`terraform import netbox_site.x 12`) or through an `import` block
  with `identity = { id = 12 }`.
* Data sources look an object up by `id`, by a small set of unique attributes (for example `name` or `slug`) or by
  arbitrary API filters (`filters = [{ name = "tenant_id", value = "3" }]`). List data sources return `items`.

## Schema

### Optional

- `allow_insecure_https` (Boolean) Skip TLS certificate verification. Default `false`. Env: `NETBOX_ALLOW_INSECURE_HTTPS`.
- `api_token` (String, Sensitive) NetBox **v2** API token in the form `nbt_<key>.<secret>`, sent as `Authorization: Bearer ...`. Legacy v1 tokens are not supported. Env: `NETBOX_API_TOKEN`.
- `headers` (Map of String) Extra HTTP headers sent with every request (for example for a reverse proxy). `Authorization` cannot be overridden.
- `max_retries` (Number) Number of retries after the first attempt for network errors, `429` and `5xx` responses (except `501`). Default `4`. Env: `NETBOX_MAX_RETRIES`.
- `request_burst` (Number) Burst capacity of the rate limiter. Only used when `requests_per_second` > 0. Default `10`. Env: `NETBOX_REQUEST_BURST`.
- `request_delay_ms` (Number) Fixed artificial delay, in milliseconds, applied before every request. Default `0`. Env: `NETBOX_REQUEST_DELAY_MS`.
- `request_timeout_ms` (Number) Timeout for a single request attempt, in milliseconds, excluding time spent waiting on the rate limiter. `0` disables the timeout. Default `60000`. Env: `NETBOX_REQUEST_TIMEOUT_MS`.
- `requests_per_second` (Number) Sustained request rate of the client-side token-bucket limiter shared by all resources. `0` (the default) disables rate limiting. Env: `NETBOX_REQUESTS_PER_SECOND`.
- `retry_wait_max_ms` (Number) Maximum backoff between retries, in milliseconds (also caps `Retry-After`). Default `30000`. Env: `NETBOX_RETRY_WAIT_MAX_MS`.
- `retry_wait_min_ms` (Number) Minimum backoff between retries, in milliseconds. Backoff is exponential with full jitter; `Retry-After` is honoured on `429`/`503`. Default `1000`. Env: `NETBOX_RETRY_WAIT_MIN_MS`.
- `serialize_requests` (Boolean) When `true`, at most one request is in flight at any time. Default `false`. Env: `NETBOX_SERIALIZE_REQUESTS`.
- `server_url` (String) Base URL of the NetBox instance, e.g. `https://netbox.example.com`. A trailing `/` or `/api` is ignored. Env: `NETBOX_SERVER_URL`.
- `skip_version_check` (Boolean) Skip the `GET /api/status/` call made when the provider is configured. By default the provider verifies the token and warns when the server is not NetBox 4.7.x. Default `false`. Env: `NETBOX_SKIP_VERSION_CHECK`.
- `user_agent` (String) Value of the `User-Agent` header. Default `terraform-provider-netbox/<version>`. Env: `NETBOX_USER_AGENT`.
- `write_delay_ms` (Number) Additional delay, in milliseconds, applied before every POST, PUT, PATCH and DELETE request. Default `0`. Env: `NETBOX_WRITE_DELAY_MS`.
