# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Terraform provider for NetBox 4.x (plugin framework, protocol 6). Most code is **generated** from the pinned
OpenAPI document in `spec/` (version in `spec/VERSION`); see @docs/GENERATOR.md before touching resources.

## Generated code: never hand-edit

- `internal/provider/gen/**`, `examples/` (only dirs with a `.generated` marker; none today, so all current
  examples are hand-maintained), `templates/`, `docs/RESOURCES.md`: output of `go run ./internal/gen`. Files
  start with `// Code generated by internal/gen ... DO NOT EDIT.` Change `internal/gen/` or
  `generator/overrides/*.yaml` instead, then `make gen`.
- `docs/` (except the hand-written `*.md` guides): output of `make docs` (tfplugindocs).
- `netbox/` (API client): output of `make client-gen` (Java 17+, Python 3); only `netbox/client_extra.go` is
  hand-written. `spec/required-fixes.json` feeds both generators: run `make client-gen` and `make gen` together.
- CI fails on any diff after `make gen` and `make docs`, so always commit regenerated output.
- Regenerate a subset with `go run ./internal/gen -only site,vrf`; a run without `-only` deletes and rewrites
  every generated file. Inspect with `-list` and `-dump -only <name>`.
- Keep each resource's attribute overrides in one overrides file: files merge in name order and later files
  win silently.

## Commands

- `make build`, `make test` (unit tests, `./internal/...`), `make fmt` (gofmt; goimports local prefix is
  `github.com/elliot/terraform-provider-netbox`).
- `make lint` only lints the hand-written packages in `LINT_PKGS` (Makefile); linting `netbox/` or
  `internal/provider/gen/` exhausts memory. Append new hand-written packages to `LINT_PKGS` (and the
  `args:` list in `.github/workflows/test.yml`).
- `make gen-check`, `make docs-check` mirror CI.

## Acceptance tests

- Need `TF_ACC=1`, `NETBOX_SERVER_URL`, `NETBOX_API_TOKEN` (v2 only: `nbt_<key>.<secret>`). Run only the
  affected tests: `TF_ACC=1 go test ./internal/provider/gen/<app>/ -run 'TestAcc<Resource>_basic' -v`.
- Target: demo.netbox.dev when it runs the pinned NetBox version (`make demo-token`, then
  `set -a; . ./.env.demo; set +a`, and `NETBOX_REQUESTS_PER_SECOND=5`); for an older version use the local
  stack (`make docker-up`, token via docker/README.md). The demo resets daily; re-run `make demo-token` on 403s.
- In sandboxes set `TF_ACC_TERRAFORM_PATH` to a local Terraform binary, or the harness hangs contacting
  checkpoint-api.hashicorp.com and the whole test binary fails.
- `make sweep` deletes every `tfacc-*` object on whatever `NETBOX_SERVER_URL` points at.

## Conventions

- Foreign keys are Int64 `<field>_id`; many-to-many are Set of Int64 `<singular>_ids`; generic relations keep
  `*_object_type` / `*_object_id`. `tags` is a set of tag slugs. `custom_fields` is a dynamic object in
  resources (only configured keys tracked) and a JSON string in data sources.
- Attributes with a server default are `Optional+Computed` with `UseStateForUnknown`; reverse sides of
  relations are `Computed` only. Updates are PATCH from the full plan.
- Hand-written resources live in `internal/provider/manual/` and register from `init()` via
  `provider.RegisterResource` / `provider.RegisterDataSource`.
- Tests are `TestAcc<Resource>_basic`. Fixture objects must contain `tfacc-` (use `{{.Name}}`) so sweepers
  find them, and the resource under test must be named `<type>.test`.

## Repo etiquette

- Branches `feat/...`, `fix/...`, `chore/...` (the labeller maps `feat/`/`fix/` to labels); Conventional
  Commits; PRs are squash-merged, so the PR title must be a conventional-commit subject.
- Do not edit `CHANGELOG.md`; it is written when cutting a release. Remove finished items from
  `docs/ROADMAP.md` as they land.
- Workflows: pin actions to full commit SHAs with a `# vX.Y.Z` comment, start from `permissions: {}`, set
  `persist-credentials: false`, never use `pull_request_target`; zizmor and CodeQL run in CI (see SECURITY.md).
